# KIKORI — Forest Watersheds

雪の森で主人公を動かし、自分で切る・背負う・運ぶ・橋を建てる3D木こりゲーム。Godot 4.5.2 Compatibility / WebGL 2、スマホ縦画面と片手操作が中心です。

公開版: https://dukutogo0101-byte.github.io/kikori-godot/ 。PRのActionsから `kikori-web` をダウンロードして、下記のHTTPサーバーでも試せます。

## 基地から広がる三つの流域

- 地形を全面的に再設計。陸地の外形は31,372m²（従来2,016m²の約15.6倍）。盆地・丘陵・高原には、起伏、入り組んだ川岸、湖、岩場、自然な間隔の森林があります。
- 中央基地のすぐそばから開始。橋を建てて北へ進み、約70m先の琥珀の丘陵、約170m先の白樺の高原を順に開拓します。
- **換金先は中央基地の出荷場ひとつだけ**。現地倉庫への搬入や、荷車が出発した時点では入金されません。主人公・荷車が基地へ届けてから入金されます。
- 基地から58m以上の森は良質材（価格2倍）、135m以上の奥地は最良質材（3倍）。樹種に加えて品質を一本ずつ保存し、中継や再読み込みでも価格を保ちます。
- 「全体地図」で現在地・基地・橋・森・道路を確認。「視野」は広い32m／最大46m（縦画面）へ拡大しました。
## 自由配置の設備と生産ライン

左上の「建設・物流」から設備を選び、地面をタップしてプレビューを確認し、確定すると建設します。「移動」で地図をずらせます。道路の下書きは移動・画面回転・指を離しても残り、その先へ延長できます。画面端で指を保持すると自動スクロールします。「一区間戻す」で最後の区間だけ戻し、「下書き消去」で取り消せます。水・岩・未開放の土地・生きた木・道路・他の建物には重ねられません。設備は全体で16棟まで。

| 設備 | 建設費 | 役割 |
|---|---:|---|
| 中間集積所 | 180 | プレイヤーと木こりNPCの納品先。丸太・加工材・製品を保管 |
| 加工所 | 320 | 丸太を一本ずつ加工材へ。中央基地での売価2倍 |
| 製品工場 | 600 | 加工材を一本ずつ製品へ。中央基地での売価4倍 |
| 道路 | 1マス2、最大1,200マス | 荷車の走行路。主人公も15%速く歩けます |
| 輸送車 | 人力120、全建物数＋1台まで | 人力 → 馬車 → トラック、各5レベル。最大3件の循環命令（詳細は下記） |

**設備そのものをタップ**すると、その設備の強化・在庫・稼働状況・手動搬入／取り出しを設定できます。右上の「道具」にはプレイヤーの道具強化だけを残しました。設備は **木造→石造→鉄骨造**、それぞれLv.1〜5です。Lv.5で高額の構造更新費を払うと次の構造のLv.1へ進みます。設備の位置・入口・在庫は維持します。加工所・工場には搬入待ちと完成品の保管枠がそれぞれあります。

| 構造 | 容量 Lv.1→5 | 加工秒数 Lv.1→5 | 次の構造への更新費 |
|---|---|---|---|
| 木造 | 64→320 | 6→1.2 | 通常建設費の30倍 |
| 石造 | 512→1,024 | 約0.857→0.545 | 通常建設費の300倍 |
| 鉄骨造 | 1,536→2,560 | 約0.316→0.261 | Lv.5で完成 |

同じ構造内の強化費は、通常建設費×構造倍率（1/10/100）×1.8の現在レベル乗を四捨五入した額です。

建設画面の「規模」で **大型** を選べます。縦横2倍・面積4倍の敷地が必要で、同じ種類・構造・レベルの通常建物に対して保管容量・加工速度が6倍。大型中間集積所は独立した木こり6人が働きます。建設・レベル強化・構造更新費は通常の5倍です。通常建物と大型建物は新設時に選び、構造更新では敷地の大きさを変えません。

中間集積所には木こりNPCが付き、構造とレベルに応じた半径17〜63mの到達可能な木を探して歩き、伐採して集積所まで運びます。満杯なら作業を待ちます。設備画面で休止すると、手持ちの荷物は納品してから止まります。

1. 設備の入口の円の中心同士を道路でつなぎます。始点と終点のタップ、またはドラッグで直線を指定し、金額を確認して確定します。直角モードではL字につなげられます。既存の黄土色の道と完成した橋は最初から荷車の経路として使え、新しく追加する区間だけ費用がかかります。生きた木は先に伐採し、川には橋が必要です。
2. 建設・物流で出発地と配送先を選び、荷車を購入します。中間集積所→加工所→工場→中央基地とつなぐと製品まで自動で運べます。途中段階からの基地への直送や、中間集積所どうしの中継にも対応します。
3. 手動で運ぶ時は入口の円で停止。通常は搬入し、設備をタップして「取り出し」に変えると完成品・保管品を背負えます。加工所は丸太、工場は加工材だけ受け入れ、対象外の荷物は手元に残ります。

加工しても樹種・産地品質・一本ごとのIDを保ちます。中間設備では入金されず、中央基地への納品でのみ入金します。配送先の空きを荷積み時に予約し、満杯の加工出力は入力を消さず待機します。

荷車の命令はいつでも変更・追加・削除・全解除できます。配送中は積荷を元の配送先へ届け、空荷で移動中は現在の出発地に到着してから、最新の命令1へ切り替えます。運行中は運行を続け、休止中は休止を保ちます。「変更予約」を表示し、予約中も再編集でき、保存・再開で引き継ぎます。「休止」は配送後に停止します。使用中の道路・既存道・橋は撤去できず、撤去の払い戻しはありません。設備・道路・作業員の経路では木の再生を待ちます。編集・メニュー・非表示の間はゲーム時間が止まります。

旧固定設備は新方式へ移行します。旧伐採所・倉庫は同じ入口に中間集積所として残し、購入費を一度だけ返金。旧作業員の荷物も集積所へ移し、既存道路・配送中の荷車は保持します。旧製材設備・運搬係の購入費も返金し、固定工房への投入は一本10で精算します。固定工房や製材設備の受動的な売価補正は廃止しました。

## 遊び方

- ゲーム領域を押してドラッグすると、その場所に仮想スティックが出ます。指を離すと止まります。PCはWASD／矢印キー、またはマウスのドラッグです。
- 木に近づいて止まると自動で伐採します。範囲内の木を一度に切り、移動すればすぐ中断します。金色の輪は伐採範囲と対象、緑の輪は収集範囲です。
- 丸太は近づくと自動で背中へ。荷物は見た目と数値の両方で確認できます。満載でも歩く速さは変わりません。
- 拠点の**金色の出荷場**で止まると一本ずつ荷下ろしし、売上が入ります。最初から使えます。
- 右上の「道具」から、伐採威力・伐採範囲・収集範囲を強化できます。費用・上限・次の効果を表示します。メニュー中は作業を停止します。
- **青い建設エリア**で止まると木材を投入します。途中で離れても投入量は残ります。橋の完成前は対岸へ行けません。
- 音と振動は初期OFF。強化画面で任意にONにできます。振動は対応ブラウザのみです。

最初の目標は、雪松を切って6本の丸太を売り、60で伐採範囲を強化すること。その後、橋へ60本を運んで琥珀の森へ進みます。

| 場所・建設 | 木材・効果 |
|---|---|
| 雪松の森 | 耐久3、3本、売値10／本 |
| 森への橋 | 木材60本で完成。琥珀の森を解放 |
| 琥珀カラマツ | 耐久7、4本、良質材48／本 |
| 白樺への橋 | 木材120本で完成。銀の森を解放 |
| 銀の白樺 | 耐久12、5本、最良質材150／本 |

移動速度は最初から6.5m/s、積載は128本で固定です。靴・リュックの成長要素は廃止しました。伐採威力の初回価格90、伐採範囲60、収集範囲80。以降は1.65倍で、初期を含め各7段階です。威力1→7、伐採半径1.62→7.6m、収集半径1.65→8.5mへ伸びます。道具は手斧→長柄斧／大なた→丸のこ→双刃ハーベスターと変化し、刃も回転します。木は32／40／48秒で再生し、主人公が切り株に重なる間は再生を待ちます。

## ホーム画面へインストール

Android Chromeで公開URLを直接開くと、利用状況に応じてChromeがインストールを案内します。「道具」の下部にある「ホーム画面に追加 / アプリの更新」からも案内を開けます。対応する案内が来ていればボタンでネイティブの確認画面を開き、まだ来ていなければChromeメニューの操作を表示します。表示時期や、拒否後の再表示はChromeが決定します。

インストール後はホーム画面から独立した画面で起動できます。初回の準備が完了すると、同じ端末で通信がなくても起動できます。セーブは同じオリジンのlocalStorageを使用します。ブラウザデータ削除ではセーブとオフラインデータも消えます。

新バージョンは完成した一式を準備して待機します。メニューで「保存して新しいバージョンへ」を押すと、保存成功を確認してから更新します。保存できなければ現在のゲームを続けます。版ごとに異なる本体URLとキャッシュを使い、プレイ中の別タブを強制的に再読み込みしません。

## 保存と互換性

3秒ごと（大量在庫時は30秒ごと）、強化・完成時、タブの非表示やフォーカス喪失時に保存します。主人公位置、荷物、地面の資源、伐採途中、強化、建設投入、解放状態を復元します。危険な位置からは安全な拠点へ戻します。

保存スキーマはv9。v7/v8の設備は同じレベルの木造・通常規模へ移行し、在庫・購入費・作業員・輸送車を保持します。保存は同期gzip圧縮で大型の在庫に対応し、従来のJSON保存も読み込めます。v7の輸送車とv5/v6セーブを検証して引き継ぎ、旧設備の購入費を一度だけ返金します。v5の靴・リュック代も返金します。伐採威力、現在地、木材、設備、道路、橋は維持します。保存キーは継続して **`kikori.watersheds.v5`**、ネイティブは `user://kikori_watersheds_v5.json`。旧 `kikori.adventure.v2` / `kikori_adventure_v2.json` / `kikori.phase1.v1` / `kikori_save.json` は読み込まず削除もしません。旧資金で序盤が飛ばない別セーブです。**留守中に主人公が作業する処理はありません。** 壊れたデータや異なるバージョンは安全に新規開始し、保存不可ならそのタブ内で続行できます。別端末への同期はありません。

## GUI不要ビルド・起動

Linux x86_64、Python 3、Node.js 18以降が必要です。公式GodotとWebテンプレートをSHA-256で検証します。

```bash
python3 tools/install_godot.py
export PATH="/tmp/kikori-godot-tools:$PATH"
bash tools/build_web.sh
python3 -m http.server 8000 --directory build/web
```

`http://localhost:8000` を開きます。WebAssemblyは `file://` では動きません。Godotエディターなら `project.godot` を開いてF5。既存Godotを使う場合は `GODOT_BIN=/path/to/godot bash tools/build_web.sh`。

ダウンロードした `kikori-web` も全ファイルを同じフォルダーへ展開し、そのフォルダーをHTTPで配信してください。

```bash

python3 tests/browser_logistics.py
LIBGL_ALWAYS_SOFTWARE=1 xvfb-run -a python3 tests/browser_smoke.py --engine webkit
```

経営ルートのテストは移動時間を含め、資源を集めて売り、3種の強化、橋、新しい森、生産ラインを実際の状態更新で通します。通路、売却・建設の保存則、二重ID拒否、購入価格・上限、部分投入の再開、破損データ拒否、地形内からの安全復帰も検証します。流域テストは1m間隔の地面を探索し、全ての木に基地から通じる歩行経路があること、川・湖・岩場・建物との衝突、遠方の材の価格、基地以外で入金されないことを検証します。シーンテストは入力キャンセルと一時間分の表示プール更新を確認します。

ブラウザテストはGodotの実Web出力に入力し、Chromeではプロトコルのタッチドラッグ、両エンジンではPC操作とUIタップを試します。Chromeの長いルートは橋を完成させ、新しい木を切って売却し、セーブを再読み込みします。状態を変えるゲーム用APIは用意していません。`window.kikoriState` / `window.kikoriUi` は診断用の読み取り要約です。

Actionsの `kikori-test-reports-chromium-*` / `kikori-test-reports-webkit-all` にJSONと実際のスクリーンショット、`kikori-web` に遊べる出力を保存します。現時点の結果・テンポ・実機未確認項目は [docs/QA.md](docs/QA.md) に記録します。

移動は旧10Hz経営更新を使わず、物理フレームで更新します。カメラは方向を回転せず、画面の上下左右と操作を一致させます。GUIを避けた入力開始、解除時のキー履歴クリア、キャンセル／非表示／回転のリセットで暴走を防ぎます。

一本ごとの資源IDを、地面→荷物→売却／建設へ論理上で一度だけ移します。見た目の飛翔は状態を変更しません。途中保存で飛翔は再現せず、確定済みの資源状態から再開します。丸太の保存則と建設投入総量、伐採回数、売上と購入代金を検証してから一括復元します。

地面の資源は最大160本、荷物128本、飛翔・木くずは固定48スロット。地面と荷物を種類別MultiMeshで表示します。容量不足の丸太は残し、地面の上限が近いと新たな伐採を待ちます。静的な地形と小物を結合し、木はメッシュを共有します。影は1灯1024px、3Dは80%解像度、重い物理・GI・ポスト処理はありません。

Web用の3D形状50点と効果音7点は、ビルド時に同じGodotで事前生成し、ゲームでは完成済みのリソースを読み込みます。起動時の大量の形状生成を避け、同じ形を共有します。Webではスクリプトをテキスト形式、フォントと生成リソースを非圧縮で出力し、読み込み時の互換性を優先します。`tools/build_web.sh` が生成と検証を行います。

Webはシングルスレッドで、SharedArrayBuffer／COOP／COEPは不要。WebKitのフレームバッファ出力対策 `web/framebuffer_guard.js` は保持し、専用の中間バッファ経由に改善しています。画面サイズに応じたRGBAバッファを1つだけ再利用し、ChromeとWebKitで実際に画像が更新されることを検証します。Safari系では描画バッファを保持します。[上流報告](https://github.com/godotengine/godot/issues/122816)。Android Chrome／iPhone SafariのWebGL 2を対象にしていますが、実機で安定30fpsを測定したとは主張しません。

## CIと公開の境界

PRはビルド・テスト・成果物だけを作ります。`deploy` と `verify-live` はmain以外で実行しません。mainへのマージ後、ビルドと両ブラウザのテストが成功するとPagesへ公開し、公開URLも検証します。

有料サービス、APIキー、サーバー、DBは不要。外部作品の素材は使いません。コードと独自素材はMIT、日本語フォントはSIL OFL 1.1。[ASSET_LICENSES.md](ASSET_LICENSES.md) を参照してください。

### 輸送車の成長と運送命令

- 人力・馬車・トラックの各車種で Lv.1〜5。Lv.5 で高額の更新費用を払うと次の車種の Lv.1 に進みます。最後はトラック Lv.5。車種ごとに描画も変わります。

| 車種 | 積載量 Lv.1 → Lv.5 | 速度 Lv.1 → Lv.5 | 各レベルの強化費 | 次の車種への更新費 |
|---|---:|---:|---|---:|
| 人力 | 8 → 24 本 | 3.3 → 5.3 | 90 / 180 / 360 / 720 | 6,000 |
| 馬車 | 128 → 256 本 | 12 → 18 | 1,800 / 3,600 / 7,200 / 14,400 | 80,000 |
| トラック | 1,024 → 2,048 本 | 36 → 52 | 20,000 / 40,000 / 80,000 / 160,000 | — |

- 購入は人力 Lv.1、120。強化・車種更新中も積み荷と道路上の位置を保持します。大容量の積み荷は最大24束で描画し、実数をラベルに表示します。
- 上限は「中央基地を含む全建物数＋1台」＝配置設備数＋2台（最大18台）。以前の保存に上限超過の車両があっても破棄せず、上限に空きができるまで追加購入を止めます。
- 各車に最大3件の `出発地 → 配送先` を登録でき、命令1 → 2 → 3 → 1と循環します。例：A → B、B → C、D → 基地。区間間と最後から最初の出発地へも、接続された道を空荷で実走します。
- 建設・物流で区間を選び、各車の「選択区間を命令に追加」または個別の「選択区間に変更」を使用。運行中の編集は自動反映、休止中は「再開」で運行。休止は現在の荷物を届けてから。荷物がない・配送先満杯の命令は1秒待ち、次の命令を試し、周回時に再確認します。
- 配送先の空きは積載時に予約。配送中の命令編集は変更予約として保存し、今回の配送先・積荷・貨物予約・走行経路を保持。変更前後の命令と空荷移動に必要な道路も撤去できません。加工・製品化と車種更新自体では収入は発生せず、中央基地への納品のみ支払い。
- 保存は同期gzip圧縮で、展開後64 MB・保存文字数240万文字まで。上限超過時は既存データを保持し、書き込みを中止します。保存形式 v9（変更予約は追加の任意フィールド）。v7の車両は既存レベル・積み荷・進行位置・費用を保持して、人力車と単一命令へ移行。v5/v6 の既存移行にも対応。v8/v9 の車種・命令数・現在命令・経路・貨物予約を厳密に検証します。
- `tests/test_transport.gd` は全15レベル、更新費用、3命令循環、空荷接続、予約競合、配送後休止、v7移行、不正保存の原子的拒否、大容量描画と、最大台数で必要になる108本の経路を繰り返し計算しないことを検証。`tests/browser_transport.py` は Chrome / WebKit で実際の操作・配送・保存再開を確認します。
